# Участие в разработке

zapret-ui — одно приложение для **Windows 10/11 x64** и **macOS 14+ Apple Silicon**.
Общие функции развиваются в одной кодовой базе и выходят в одном релизе для обеих
платформ. Перед изменениями прочитайте [`AGENTS.md`](AGENTS.md): там описаны
архитектура, контракты UI и особенности системных адаптеров.

Участвуя в проекте, вы соглашаетесь соблюдать
[Кодекс поведения](CODE_OF_CONDUCT.md).

## С чего начать

- Ошибки и предложения оформляйте через
  [issue](https://github.com/MelDxKviel/zapret-ui/issues), указав ОС и версию приложения.
- Если проблема воспроизводится в оригинальном ядре без zapret-ui, обращайтесь
  в соответствующий upstream:
  [Windows](https://github.com/Flowseal/zapret-discord-youtube/issues) или
  [macOS](https://github.com/Flowseal/zapret-mac-discord-youtube/issues).

## Окружение и проверки

Rust закреплён в [`rust-toolchain.toml`](rust-toolchain.toml); rustup установит
нужную версию. Windows требует MSVC Build Tools и `x86_64-pc-windows-msvc`, Mac —
Xcode Command Line Tools и `aarch64-apple-darwin`. Используйте обычный терминал
без прав администратора.

Общие команды:

```sh
cargo fetch --locked
cargo fmt --all -- --check
cargo clippy --frozen --all-targets --all-features -- -D warnings
cargo test --frozen --all-targets --all-features
cargo run --locked --example ui_only
```

`cargo fetch` заранее загружает зависимости; проверки с `--frozen` используют
lockfile без сети. Обычные тесты не обращаются к внешним сервисам и не меняют
сетевые настройки; локальные loopback-тесты Telegram запускаются на обеих ОС.
Live-тесты Telegram требуют явного `-- --ignored` и не входят в CI. Реальную
установку/запуск службы и обход проверяйте отдельно на тестовой машине.

`ui_only` показывает общий интерфейс Slint с моками: без реального скачивания,
процессов ядра, службы или системного запроса администратора. Это быстрый способ
дорабатывать UI.

Сборка для распространения:

- Windows: `cargo build --locked --release` → `target/release/zapret-ui.exe`.
- Mac: `sh scripts/build-macos.sh` → `.app`, ZIP, DMG и SHA-256 в `dist/`.
  [Подробности macOS](docs/macos.md).

На Windows релизный EXE запрашивает UAC; отладочные сборки остаются `asInvoker`.
На Mac GUI всегда работает без повышения прав: авторизация запрашивается только
для системных операций ядра. Не запускайте Mac GUI или тестер через `sudo`.

## Общий код и адаптеры

- `ui/` — единый интерфейс Slint, темы и страницы для обеих ОС.
- `src/lib.rs` — единая библиотека приложения; `src/main.rs` и `ui_only`
  используют её модули и сгенерированные типы Slint без повторной компиляции UI.
- `src/app/` — общий оркестратор и обработчики команд; `src/contracts.rs` — типы
  `Strategy`, `RuntimeStatus`, `BackendCmd`, `UiEvent`.
- `src/ports.rs` — восемь интерфейсов: `Installer`, `SelfUpdater`, `Runner`,
  `ServiceCtl`, `StrategyCatalog`, `StrategyTester`, `Maintenance`, `TelegramProxy`.
- `src/config.rs`, `src/log.rs`, `src/i18n.rs`, `src/telegram/` — общие настройки,
  журнал, переводы и локальный Telegram proxy.
- `src/app_dirs.rs` и `src/download.rs` — общие пути данных и потоковая загрузка
  с лимитом размера, прогрессом и SHA-256 для установщика ядра и обновления GUI.
- `src/zapret/` — загрузка, обновление, тестирование и адаптеры ядер. Windows
  читает `.bat` и запускает `winws.exe` процессом или службой SCM; Mac читает TSV
  и управляет `utunws` через launchd и upstream-скрипты.
- `src/platform/macos/` и Windows desktop helpers — нативная интеграция с ОС
  (окна, автозапуск, уведомления, один экземпляр приложения).

Пишите общую реализацию, если поведение совпадает. Добавление страницы, настройки
или исправление бизнес-логики должно работать на обеих платформах без копирования
UI/оркестратора. Отделяйте только различия API ОС, формата ядра и его возможностей
за портами или небольшими `cfg`-блоками в адаптерах. У macOS нет режима пользовательского
процесса и GameFilter; это различие ядра, а не повод создавать отдельный интерфейс.

Команды UI (`BackendCmd`) уходят в mpsc-канал, события (`UiEvent`) возвращаются
через broadcast. Свойства Slint обновляйте только через слушатель `UiEvent` или
`slint::invoke_from_event_loop`, никогда напрямую из фоновой задачи.

## Контракты, которые нужно сохранить

- Имена `callback`/`in-out property` в `ui/main_window.slint` согласованы с
  `src/app/mod.rs` и `examples/ui_only.rs`. Изменение требует обновить обе стороны.
- Каждая видимая строка использует `I18n.t(I18n.lang, "ключ")`. Ключи добавляются
  сразу в `src/locales/ru.json` и `src/locales/en.json`; платформенные формулировки
  остаются в этих общих каталогах.
- Тесты по умолчанию импортируют production-код из `zapret_ui`; не копируйте
  дерево модулей через `#[path]`. Исключение — чистые адаптеры форматов, которые
  намеренно проверяются и на другой ОС.
- Стратегии загружаются из установленного ядра, не из захардкоженного списка.
- Приложение не вызывает `api.github.com`: версии и файлы получает через raw,
  codeload, Atom-ленты и release assets.
- Не добавляйте постоянные таймеры, перерисовки и сетевые задачи для выключенных
  функций. Telegram должен оставаться независимым от ядра и повышения прав.

## Pull request

1. Создайте ветку от `main`; отдельная постоянная ветка продукта для Mac не нужна.
2. Реализуйте общее поведение в общем коде. Объясните неизбежные платформенные
   различия, если они добавляются.
3. Выполните общие проверки выше и убедитесь, что в CI успешны **оба** нативных
   задания: Windows x64 и macOS ARM64. Не считайте проверку одной ОС проверкой другой.
4. Опишите проверенные сценарии и ограничения: на какой ОС тестировали локально,
   что проверил CI, какие системные сценарии пока не проверены. UI и системные
   изменения проверяйте на соответствующих платформах.
5. Обновите документацию и заполните шаблон PR; свяжите issue, если оно есть.

Один workflow `CI / Release` проверяет, тестирует и упаковывает обе платформы на
push/PR и по ручному запуску. Публикация только по тегу `v*`, после успеха обеих
сборок, с общим номером версии и полным набором файлов. Подробности — в
[`docs/RELEASING.md`](docs/RELEASING.md).
